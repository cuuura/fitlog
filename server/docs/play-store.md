# Google Play 등록 가이드 (개인정보·데이터 보안)

서버가 실제로 저장하는 정보(계약 `contracts/v1.0/privacy-policy.md`, DB 스키마 V1~)를 기준으로 쓴 답안이다. Play Console 화면 문구는 바뀔 수 있으니 항목 이름이 다르면 가장 가까운 것을 고른다. **제출 전에 앱 쪽 실제 동작(광고 SDK, 크래시 수집 도구 등)과 일치하는지 사용자가 확인해야 한다.**

## 1. URL

배포한 서버 주소(`PUBLIC_BASE_URL`)가 `https://fit.example.com` 이라면:

| Play Console 항목 | 값 |
| --- | --- |
| 개인정보처리방침 URL | `https://fit.example.com/privacy` |
| 계정 삭제 URL(데이터 보안 → 계정 삭제) | `https://fit.example.com/account-deletion` |
| 연락처 이메일 | `.env` 의 `CONTACT_EMAIL` 과 같게 |

두 페이지는 로그인 없이 열리고, 서버 환경 변수(`CONTACT_EMAIL`, `POLICY_EFFECTIVE_DATE`, `BACKUP_RETENTION_DAYS`)로 값이 채워진다. 계정 삭제 페이지에는 앱 이름, 삭제 방법(설정 → 계정 → 계정 삭제), 이메일 요청 방법, 삭제·보관 항목과 기간이 있다(Play 요건).

## 2. 데이터 보안 양식 답안

### 개요 질문

| 질문 | 답 | 근거 |
| --- | --- | --- |
| 앱이 사용자 데이터를 수집·공유하나요? | 예(수집함) | 계정·건강·운동 기록을 서버에 저장 |
| 전송 중 데이터 암호화 | 예 | HTTPS(Caddy 자동 인증서) |
| 사용자가 데이터 삭제를 요청할 수 있나요? | 예 | 앱 내 계정 삭제 + 웹 URL + 이메일 |
| 데이터 삭제 방법 | 앱 안 + 웹 링크 제공 | 위 URL |
| Play 가족 정책 | 해당 없음(만 14세 미만 사용 불가) | 방침 7항. 대상 연령층은 성인으로 선택 |
| 독립적 보안 검토 | 아니오 | |

### 수집하는 데이터 유형

| 범주 | 항목 | 수집 | 공유 | 처리 목적 | 필수/선택 | 근거 |
| --- | --- | --- | --- | --- | --- | --- |
| 개인 정보 | 이름 | 예 | 아니오 | 앱 기능, 계정 관리 | 필수 | Google 로그인 프로필 |
| 개인 정보 | 이메일 주소 | 예 | 아니오 | 앱 기능, 계정 관리 | 필수 | Google 로그인 |
| 개인 정보 | 사용자 ID(Google 계정 식별자 sub) | 예 | 아니오 | 앱 기능, 계정 관리 | 필수 | 계정 식별 |
| 건강 및 피트니스 | 건강 정보(체중, 키, 성별, 출생 연도) | 예 | 아니오 | 앱 기능 | 선택(입력할 때) | 건강정보 처리 동의 후에만 저장 |
| 건강 및 피트니스 | 피트니스 정보(운동 기록: 종목·무게·횟수·RPE/RIR·휴식·메모, 1RM) | 예 | 아니오 | 앱 기능 | 필수(핵심 기능) | |
| 앱 활동 | 앱 내 활동(AI 연결 이름·시각, AI가 넣은 데이터 출처 표시) | 예 | 아니오 | 앱 기능 | 선택(AI 연동을 쓸 때) | |
| 앱 정보 및 성능 | 비정상 종료 로그·진단 | 예 | 아니오 | 분석(오류 수정) | 선택 | 운동 기록·이메일 미포함. 오류 수집 서비스를 쓰는 경우 |
| 기기 또는 기타 ID | 기기·보안 판정(Play Integrity 결과) | 예(무결성 켠 경우) | 아니오 | 부정 사용 방지, 보안 | 필수 | 판정 결과만, 기기 식별자는 저장하지 않음 |

수집하지 않음(체크 안 함): 위치, 연락처, 사진·동영상, 오디오, 파일, 결제 정보, 웹 탐색 기록, 광고 ID.

참고
- **접속 IP**는 호출 제한을 위해 메모리에서만 쓰고 저장하지 않는다(방침 4항). 그래서 "기기 또는 기타 ID/IP" 수집으로 신고하지 않는다. 서버 앞단(호스팅, Caddy)의 접근 로그에 IP 가 남는 설정이라면 그에 맞게 `서버 로그` 보관을 확인한다.
- **공유 = 아니오**로 답하는 근거: 서버 호스팅·오류 수집은 "서비스 제공업체"의 처리라 Play 정의상 공유가 아니고, AI 서비스(Claude·ChatGPT·Gemini)로의 전달은 사용자가 직접 연결하고 허용한 범위에서만 일어나는 사용자 주도 전송이다. 법률 자문이 필요하면 확인한다.
- 모든 데이터는 **암호화 전송**, 계정 삭제 시 **즉시 삭제**(백업은 최대 `BACKUP_RETENTION_DAYS`일 후 소멸 — 방침·삭제 페이지에 명시).
- 건강 정보 앱 선언: Play Console 의 "건강 앱" 선언 양식에서 "피트니스 / 운동 기록" 유형을 선택한다. 의료 기기·진단 용도가 아님을 밝힌다.

## 3. 사용자가 직접 해야 할 일

1. **서버 배포**: 도메인·HTTPS·`.env` 값(특히 `CONTACT_EMAIL` 은 실제 받는 주소, `POLICY_EFFECTIVE_DATE`, `PUBLIC_BASE_URL`)을 정하고 `docs/ops.md` 대로 올린다. 배포 후 두 URL 을 브라우저로 열어 확인한다.
2. **방침 확인**: `/privacy` 내용이 실제 앱과 맞는지 읽어 본다(오류 수집 서비스 이름, 호스팅 위치 등). 바뀌면 `contracts/v1.0/privacy-policy.md` 를 고치고 다시 배포한다. 시행일 7일 전 공지 약속(방침 8항)을 지킨다.
3. **Play Console 입력**: 위 1·2장대로 개인정보처리방침 URL, 데이터 보안 양식, 계정 삭제 URL, 건강 앱 선언, 콘텐츠 등급, 대상 연령층을 입력한다.
4. **Play Integrity 연동**(선택, 나중): Google Cloud 프로젝트 번호를 앱 빌드(`PLAY_CLOUD_PROJECT_NUMBER`)에 넣고, 서비스 계정 JSON 을 서버에 마운트해 `PLAY_INTEGRITY_CREDENTIALS` 를 지정한 뒤 `INTEGRITY_MODE=report` 로 시작해 판정이 정상인지 보고 `enforce` 로 올린다.
5. **백업 점검**: 실제 서버에서 일일 백업이 도는지, 원격 보관과 `restore-check.sh` 가 통과하는지 확인한다.
6. **Google 로그인 설정**: Play 앱 서명 인증서의 SHA-1 을 Android OAuth 클라이언트에 등록한다(스토어 배포 빌드는 업로드 키와 서명 키가 다르다).
7. **삭제 요청 메일함**: `CONTACT_EMAIL` 로 오는 삭제 요청을 7영업일 안에 처리할 담당·절차를 정한다(서버 DB 에서 해당 사용자 삭제).
